# Автоопределение региона на arma-lab.ru

Заметки по реализации подстановки региона посетителя в лендинг образовательной лицензии.

Задействованы два файла:

| Файл | Что в нём |
|---|---|
| `assets/js/geo-region.js` | Весь движок: словари, склонение, определение по IP, покраска слотов |
| `index.html` | Подключение скрипта в `<head>` + **две правки внутри бандла** (см. раздел 1) |

---

## 1. Правки в коде компонента формы внутри index.html

`index.html` — самораспаковывающийся бандл. Разметка и код компонента лежат
внутри одной длинной JS-строки в экранированном виде: кавычки как `\"`,
закрывающие теги как `<\u002Fa>`, переводы строк как `\n` (два байта:
обратный слэш и `n`). Правки внесены побайтовой склейкой, без форматтеров.

### Правка 1 — слушатель события, в `componentDidMount()`

Вставлена сразу после `this.initMetrika(p);`:

```js
this.onGeo = (e) => {
  if (!this.meta) return;
  const d = (e && e.detail) || {};
  if (d.readable) this.meta.geo_region = d.readable;
  if (d.phrase && /^(в|во|на)\s+\S/i.test(d.phrase)) this.meta.geo_phrase = d.phrase;
};
document.addEventListener('arma:geo', this.onGeo);
```

**Зачем.** `this.meta` собирается один раз при монтировании из параметров
адреса. Определение по IP асинхронное, и компонент часто монтируется раньше,
чем ответ пришёл. Без слушателя `geo_region` в заявке остался бы пустым.

### Правка 2 — приоритет при отправке, в `submit`

В объекте `payload`, сразу после `...this.meta`:

```js
...this.meta,
// Приоритет — актуальное значение из window.ARMA_GEO, затем состояние компонента.
geo_region: window.ARMA_GEO_REGION || (this.meta || {}).geo_region || '',
geo_phrase: /^(в|во|на)\s+\S/i.test(window.ARMA_GEO || '') ? window.ARMA_GEO : ((this.meta || {}).geo_phrase || '')
```

**Зачем.** Второй рубеж на случай, если событие по какой-то причине не
доехало. Значение перечитывается непосредственно перед отправкой.

**Важно:** эти два ключа обязаны идти **после** спреда `...this.meta` —
иначе спред их перезатрёт и приоритет развернётся наоборот.

### ⚠️ Предупреждение о пересборке бандла

**Обе правки живут внутри бандла. Любая пересборка или повторный экспорт
лендинга из конструктора перезапишет `index.html` целиком, и обе правки
исчезнут.**

Отказ будет тихим и незаметным при беглом просмотре:

- регион в заголовке **продолжит подставляться** — это делает
  `geo-region.js`, он вне бандла и не пострадает;
- но `geo_region` и `geo_phrase` в заявках станут **пустыми**;
- на странице никакой ошибки не появится, в консоли тоже.

Заметить можно только по заявкам в Битрикс24 без региона.

**После каждой пересборки:**

1. Заново внести обе правки (якоря: `this.initMetrika(p);` и `...this.meta`).
2. Проверить, что подключение `<script src="/assets/js/geo-region.js" defer>`
   осталось в `<head>` внешней оболочки.
3. Убедиться, что слоты `data-region-slot` 1, 2 и 3 на месте.
4. Отправить тестовую заявку и проверить непустой `geo_region` в n8n.

## 2. Архитектура

### Два значения, а не одно

Регион нужен в двух падежах, поэтому скрипт публикует две глобальные
переменные:

| Переменная | Падеж | Пример | Куда идёт |
|---|---|---|---|
| `window.ARMA_GEO` | предложный | `в Краснодарском крае` | Заголовок H1, `document.title`, поле `geo_phrase` |
| `window.ARMA_GEO_REGION` | именительный | `Краснодарский край` | Подпись «Ваш регион», поле `geo_region` |

Имя `ARMA_GEO` для предложной формы закреплено исходной задачей, менять
контракт не стали — именительный падеж добавлен рядом.

### Событие

```js
document.dispatchEvent(new CustomEvent('arma:geo', { detail: res }));
```

`detail` — объект `{ phrase, readable, push }`:

- `phrase` — предложная форма;
- `readable` — именительная;
- `push` — можно ли писать в адрес страницы (для зарубежных посетителей `false`).

Событие отправляется один раз, сразу после определения региона, **до**
первой покраски слотов.

### Слоты в разметке

| Слот | Исходный текст | Что подставляется | Где на странице |
|---|---|---|---|
| `data-region-slot="1"` | `в вашем регионе` | предложный падеж | Заголовок первого экрана, красный акцент |
| `data-region-slot="2"` | `Ваш регион` | именительный падеж | Карточка «Персональный план лицензирования» |
| `data-region-slot="3"` | `Ваш регион` | именительный падеж | Там же, нижняя строка |

Селектор слота 1 — `[data-region-slot="1"], .js-geo-region`. Класс
`js-geo-region` поддержан как псевдоним, но в текущей разметке не
используется: слоты уже помечены атрибутами, и лезть в бандл ради
дублирующего класса незачем.

### Передача в CRM

Заявка уходит не через отправку формы браузером, а `fetch`-ом из компонента,
телом идёт его собственное состояние. Скрытое поле `<input type="hidden">`
в этот payload **не попало бы**, поэтому его и нет.

Рабочий путь такой:

```
geo-region.js  ──history.replaceState──>  ?geo_phrase=…&geo_region=…
                                                  │
                                     componentDidMount() читает адрес
                                                  │
                          ──событие arma:geo──>  this.meta обновляется
                                                  │
                              submit(): window.ARMA_GEO перебивает meta
                                                  │
                                          POST в n8n → Битрикс24
```

Фраза пишется в адрес только если начинается на в/во/на — компонент
отбрасывает остальные по своей проверке. Поэтому для зарубежных посетителей
(`по всей России`) в адрес не пишем вовсе.

### Порядок определения региона

1. `?geo_phrase=` от рекламной кампании — скрипт молча выходит, компонент
   подставит сам.
2. `?city=`, `?region=`, `?geo=` — мгновенно, без обращения к сервисам.
3. Кеш `localStorage`, ключ `arma_geo_v3`, 7 суток.
4. Определение по IP: `ipwho.is` (таймаут 1,5 с) → `ipapi.co` (3 с) →
   `api.sypexgeo.net` (3 с).
5. Ничего не сработало — остаётся «в вашем регионе».

### Порядок разбора названия

Из ответа провайдера берётся **регион, а не город**: посетителю из Сургута
показываем «в Ханты-Мансийском автономном округе», а не «в Сургуте». Город
остаётся запасным вариантом на случай, если регион не распознан.

1. **Словарь регионов** `ENG_REGIONS` — 402 ключа на все 85 субъектов РФ.
   Покрывает и английские написания (`Tula Oblast`), и транслит с русского,
   который реально отдаёт MaxMind: `Saratovskaya Oblast`, `Krasnodarskiy Kray`,
   `Khanty-Mansiyskiy Avtonomnyy Okrug-Yugra`, `Moskva`.
2. **Словарь городов** `FORMS` — 235 ключей.
3. **Правило склонения** — для русских названий от sypexgeo и всего,
   чего нет в словарях.
4. Фолбэк: отрезать английский суффикс и попробовать как город.

Регионы проверяются строго раньше городов. Иначе `Tula Oblast` вырождается
в город Тулу — `ipwho.is` стоит первым провайдером и отдаёт латиницу,
так что это происходило бы регулярно.

`normalize()` снимает апострофы (`Tul'skaya Oblast'`) и ужимает пробелы
вокруг дефисов (`St.-Petersburg`) — провайдеры пишут названия по-разному.

### Покраска слотов

Бандл заменяет корневой элемент через `documentElement.replaceWith()`.
`MutationObserver`, подвешенный к старому корню, замену не переживает,
поэтому используется опрос `document` (сам объект не меняется):
каждые 150 мс, до 133 попыток — около 20 секунд.

## 3. Известные ограничения

### Из исходной постановки

1. Подмена выполняется в браузере. Поисковый робот видит «в вашем регионе».
   Для органического трафика нужны отдельные страницы под регионы.
2. Определение по IP неточное для мобильного интернета и корпоративных
   сетей — часто отдаётся город регистрации оператора.
3. У бесплатных тарифов гео-сервисов есть суточные лимиты. Кеш на 7 суток
   снижает нагрузку. При трафике выше нескольких тысяч визитов в сутки
   понадобится платный сервис, например DaData.
4. Малые населённые пункты вне словаря не подставляются — остаётся текст
   по умолчанию.
5. При определении по IP посетитель на долю секунды видит исходный текст.
   Через параметр в адресе этого не происходит.

### Всплывшее по ходу работы

6. **Пересборка бандла стирает правки компонента** — см. раздел 1.
   Самый неприятный пункт списка: отказ тихий.
7. **Гонка с монтированием.** Если компонент смонтировался раньше ответа
   GeoIP, параметры в адресе появятся уже после чтения. Закрыто событием
   `arma:geo` и перечитыванием при отправке, но сам порядок остаётся
   недетерминированным.
8. **Кеш переживает переезд.** Регион держится 7 суток; посетитель,
   сменивший город, до истечения кеша увидит старый. Сбрасывается
   удалением ключа `arma_geo_v3`.
9. **Правило предлога — эвристика.** «во» ставится перед в/ф/р/м с
   согласной следом. Покрывает Владимир, Владивосток, Ржев, Мценск;
   на экзотических названиях может ошибиться.
10. **Склонение регионов — тоже правило, а не словарь форм.** Работает для
    шаблонов «X край», «X область», «X автономный округ», «Республика X»
    и прилагательных республик. Название, не попадающее ни в один шаблон
    и отсутствующее в словарях, не подставится.
11. **«Республика Саха»** — намеренно короткая форма вместо официальной
    «Республика Саха (Якутия)»: скобки ломают расстановку заглавных и
    утяжеляют заголовок. Псевдонимы `Yakutia`, `Sakha (Yakutia)` работают.
12. **Крым и Севастополь** есть в словарях, потому что GeoIP-сервисы
    возвращают для этих адресов `Republic of Crimea` и `Sevastopol`.
    Записи отражают вывод провайдеров.
13. **Английские названия вне словаря регионов** по-прежнему вырождаются
    в одноимённый город через последний фолбэк. Все 85 субъектов в словаре
    есть, так что случай остаточный.
14. **Длинные названия.** «в Ямало-Ненецком автономном округе» заметно
    длиннее исходной фразы. Слоту проставляются инлайн
    `overflow-wrap: break-word` и `hyphens: auto` — правило в `<style>`
    оболочки не помогло бы, оно уничтожается вместе со старым `<head>`
    при замене корня.

## 4. Как отлаживать

### Что вернул каждый гео-сервис

```js
window.ARMA_GEO_DEBUG = true;
location.reload();
```

В консоли появится по строке на провайдера:

```
[geo] https://ipwho.is/ { country: 'RU', names: ['Krasnodar', 'Krasnodar Krai'] }
```

Видно, на каком шаге цепочка остановилась и какие названия пришли.

### Что определилось в итоге

```js
window.ARMA_GEO         // 'в Краснодарском крае'  — предложный падеж
window.ARMA_GEO_REGION  // 'Краснодарский край'    — именительный
```

### Кеш

Ключ `arma_geo_v3` в `localStorage`, срок жизни 7 суток:

```js
JSON.parse(localStorage.getItem('arma_geo_v3'))
// { v: { phrase: 'в Краснодарском крае', readable: 'Краснодарский край', push: true }, t: 1755690000000 }

localStorage.removeItem('arma_geo_v3');   // сбросить и определить заново
```

### Проверить конкретный регион без VPN

```
/?city=Ямало-Ненецкий автономный округ
/?city=Tula Oblast
/?city=Зеленоградск          // нет в словаре — текст не меняется
/?geo_phrase=в Казани        // имитация рекламной кампании: скрипт выходит
```

### Проверить, что уходит в заявку

Перед отправкой формы, в консоли:

```js
document.addEventListener('arma:geo', e => console.log('событие:', e.detail));
```

Само тело запроса — во вкладке Network, POST на вебхук n8n, поля
`geo_region` и `geo_phrase`.

### Быстрая проверка после выката

```bash
curl -s https://arma-lab.ru/assets/js/geo-region.js | head -3
curl -s https://arma-lab.ru/ | grep -c 'geo-region.js'          # 2: подключение и упоминание в комментарии
curl -s https://arma-lab.ru/ | grep -c 'ARMA_GEO_REGION'        # 1: правка 2 в компоненте
curl -s https://arma-lab.ru/ | grep -c "addEventListener('arma:geo'"   # 1: правка 1 в компоненте
```

Последние две строки — самый быстрый способ убедиться, что правки в бандле
на месте и пересборка их не стёрла.
